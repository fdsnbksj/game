# CLAUDE.md

**a game**: a mobile web nonogram game for a train ride with a book: small logic puzzles to play between chapters, each followed by one short, useful idea (psychology, software engineering, philosophy, productivity). Tap squares to fill them so every row and column matches its clue numbers. It's played with one thumb and no sound, with no clock or way to lose, and every tap is saved, so it can be put down at any moment, even offline. Levels are endless (5×5 growing to 10×10) and ranked. React handles the screens and Firebase the free-plan backend (Auth, Firestore, Hosting). Setup and layout are in `README.md`. It replaced an auto-battler, which had replaced **Neon Flap**; both left data in Firestore that is now closed (see Constraints).

## Git and deploy

- **Only the `main` branch.** Commit directly to `main`. Don't create branches or pull requests.
- **Every push to `main` deploys to production** via `.github/workflows/deploy.yml`: unit tests → build → Firestore rules tests → deploy Hosting and Firestore rules → deploy Firestore indexes. Push right after each commit so every commit is deployed.
- The index step may fail if the deploy account can't create indexes; it's allowed to, so the site still deploys, and the level rankings fail to load until the index exists. If it fails, run `npm run deploy` logged in as a project owner.
- Auth settings in `firebase.json` (anonymous sign-in) are **not** deployed by the workflow, because the deploy account lacks those permissions. After changing them, run `npm run deploy` logged in as a project owner.
- A failing build, unit test or rules test stops the deploy, so run `npm run build`, `npm run test:unit` and `npm run test:rules` before committing.
- Never commit secrets. The Firebase web config in `.env.production` is public by design. The deploy service account key lives only in the `FIREBASE_SERVICE_ACCOUNT` GitHub secret.
- The production Firebase project ID is the `default` entry in `.firebaserc`. Local development always uses the `demo-game` emulator project.

## Commands

```sh
npm run emulators   # Auth + Firestore emulators (needs Java 21: /opt/homebrew/opt/openjdk@21/bin on PATH)
npm run dev         # Vite dev server, reachable from a phone on the LAN
npm run build       # type-check + production build
npm run audit       # checks saved solves against their puzzles
npm run set-level -- --name <player> --level <n> [--write]   # admin: set a ladder's level (emulator unless PROJECT_ID=<id>)
npm run test:unit   # puzzle logic tests, no emulator needed
npm run test:rules  # Firestore rules tests (starts its own emulator; stop `npm run emulators` first)
```

## How the game fits together

- **`src/nonogram/` is the whole puzzle as pure TypeScript**: clues, a line solver, the generator and the play reducer. No DOM, React, Firebase, `Math.random` or `Date`; `tests/unit/purity.test.ts` enforces it. Every random choice comes from a named seeded stream (`src/nonogram/rng.ts`), so a level or day gives the same puzzle on every device.
- **Every puzzle is solvable by logic alone.** `nonogram(level)` draws random pictures until the line solver (`solve()`) settles every cell from the clues, which also proves the answer is unique. Each try is a little denser, and a full grid always settles, so it always ends. Changing the generator or `sizeFor()` changes every puzzle: bump `NONOGRAM_VERSION` and update the golden hash in `tests/unit/nonogram.test.ts`. A new version starts a new ladder (`ladders/{uid}_{version}`), and localStorage progress restarts with it.
- **Play is checked against the clues, not the stored answer** (`isSolved()`). Crosses are only notes. A stroke (a tap, or a drag locked to one row or column) is one undo step, and nothing is committed until the finger lifts (`src/components/Board.tsx`).
- **Home is Hero Gambit; every other game is hidden for now (the user's choice, 2026-10-09).** `/` is `src/screens/hero/Home.tsx` inside `WorldShell`: your hero standing large, the next fight, and round buttons to the skill tree, Wardrobe, Summon, the arena and a friend. The tabs are Home, Wardrobe, Summon, Ranks (the arena board only) and Me; the player bar shows your hero's face, level and gems. The other games' routes, screens and code all stay (old links still open them), the world map and zones are just unrouted, and `restoreLastPage` reopens only Hero Gambit's pages. To bring the games back, route `/` to `WorldMap` again and restore the tabs. What follows describes the map as it was.
- **A world map, zones, then one screen per game (redesigned by the user to feel like a game; Tower of Saviors was the reference).** `/` is a drawn night map (`src/screens/world/WorldMap.tsx`, one inline SVG) with three landmarks: the **Board Game Keep** (Avalon, Rival Wonders, Ancient Wonders, Island Settlers), the **Puzzle Tower** (Nonograms) and the **Battle Arena** (Hero Gambit, Stick Brawl). Each opens its zone page (`/zone/:id`, `Zone.tsx`): a framed banner, then the zone's games as stage cards, with a Continue ribbon on a game whose room is still on. `src/screens/world/zones.ts` is the one list of zones and games (`tests/unit/zones.test.ts` checks every game is in one zone and its route exists). **Hero Gambit is the main game**, so a hero banner sits across the top of the map (your hero's level, the next bot, points to spend), and a room in progress shows as a "Battle in progress" banner under it. The four tab pages (Map `/`, Cards `/saved`, Ranks `/ranks`, Me `/account`) sit inside `WorldShell`: a player bar on top (avatar, name, hero level, tower floor, cards kept, settings) and a tab bar below; they hide their back arrow (`Page` with `back={null}`) unless opened from the puzzle's ⋯ menu, which passes `state.from` (`useCameFrom`). Games' front doors go back to their zone. Nonograms live at `/nonograms` (`Play.tsx`), with a ⋯ menu to Saved cards, Rankings and Settings. Keep each game's play screen as bare as the puzzle's; the game-style frames (`.frame`, `.ribbon`, `.stage-card`) are for the map, zones, tabs and front doors only.
- **Accounts** (`src/services/account.ts`, `/account`): everyone starts as an anonymous guest (`startSession`). Creating an account links an email and password to that same user (`linkWithCredential`), so the uid, name and ladder stay. Signing in to another account switches uid; `nonogramStore.claim()` then drops the device's ladder if it belonged to someone else, and `catchUp` loads the account's level. Signing out makes a new guest. The Email/Password provider is enabled in `firebase.json`, which the workflow doesn't deploy (see above).
- **Reopens where it was left.** The installed app always starts at `/`, so `src/lastPage.ts` saves every route to localStorage (`game:lastPage`) and, when the app opens at `/`, `restoreLastPage()` (in `main.tsx`, before the router) replaces it with the saved page if it's one of the app's own. A room that's gone or under way without this phone shows a way back to the games.
- **Offline first.** `src/nonogramStore.ts` (zustand) holds the plays in progress, the ladder level, solved days and settings, and saves every change to localStorage (`game:nonogram`). The app never waits for Firebase: `startSession()` signs in in the background and retries when the connection returns.
- **Online solves:** a solve is counted locally first, then queued and written in order at least 3 s apart, as the rules require, once there's a session. A network error leaves it queued. If the rules refuse a level, the ladder carries on unranked on that device.
- **The ladder** is `ladders/{uid}_{NONOGRAM_VERSION}`: the highest level solved and each level's grid (one `0`/`1` string, row by row). The first write creates the doc at level 1. Once a session, before writing, `sync()` reads the player's ladder and `catchUp()` moves the device up to it if the server is ahead: a new phone, cleared storage, or a level set with `scripts/setLevel.ts`, which files every level's real answer so the audit stays clean.
- **A knowledge card after every puzzle:** one short idea from psychology, software engineering, philosophy or productivity, with a "Try this" line (`src/learn/knowledge.ts`, about 40 per topic; a new topic starts switched on for existing players via `offered` in `src/knowledgeStore.ts`). `pickKnowledge()` shows every card of the chosen topics before any repeats. Cards are written in our own words and name their source; hedge where the research is weaker than the popular version. `tests/unit/learn.test.ts` caps their length so they fit on a phone. Topics and saved cards live in localStorage (`src/knowledgeStore.ts`), never Firestore.
- **Avalon** (`/avalon`, `src/screens/avalon/`) is played at one table, each player on their own phone; the talking happens out loud. `src/games/avalon/` is the game as pure TypeScript: `rules.ts` (published tables), `deal.ts` (roles and night knowledge) and `state.ts`, whose `derive()` works out phase, leader, quests and winner from the documents, so every phone reaches the same state and no one has to advance the game. `src/services/avalon.ts` writes each player's own actions and follows a room live (`watchRoom`).
- **Avalon data** is `rooms/{code}` with subcollections `secrets` (each player's role, readable only by them until the game is over), `proposals`, `votes` and `quests` (tallies only: a card is a marker holding nothing, written with the tally going up by one, so no document says who played a fail). `firestore.rules` checks each write; `tests/rules/avalon.test.ts` covers them.
- **Avalon's table and the Lady of the Lake:** `playerIds` is the seating order, clockwise; the host arranges it in the lobby so the lead passes the way people really sit, and `TableView.tsx` draws the seats around an oval (leader, next, team, votes, Lady; tap to pick). While a player holds their role card, their night knowledge is marked on the seats too (Merlin's evil, Percival's Merlin-or-Morgana pair, evil's fellow evil) with a legend under the table; it all hides on release, like the card. The Lady is optional: after quests 2–4 her holder examines someone (`lady/{after}`, public) and passes her on. The examined player's own phone files their loyalty (`ladyResults/{after}`), which the rules check against their role and let only the holder read. The Lady's rules avoid `? :`: the emulator crashes on those conditionals instead of denying, and the write just hangs.
- **Rooms survive a stalled stream (every room game: Avalon, the Wonders games, Island Settlers, Hero Gambit, Stick Brawl's handshake).** On phones the main SDK's stream can wedge after the app has been in the background (switching to a chat to share the code), so listeners stop hearing changes and a write through it can sit pending forever: a real bug left two phones each waiting on the other. So room writes go over plain HTTPS (`dbRest`, Firestore Lite, in `src/firebase.ts`; each lands or fails then and there), and `src/services/resilient.ts` follows rooms: `keepFresh` remakes the listeners when the page comes back, the connection returns or one fails, and reads over HTTPS every few seconds (only while the page is showing) and right after each write of ours (`poke`). `followRoom` does this for a room plus its numbered moves (kept by number, so a move counts once however it arrives); Avalon checks counts of its collections every 10 s and reads again only what differs, to stay cheap on Spark's read quota. The hero doc and the arena go over HTTPS too. To test it, block a headless browser's `*Listen/channel*` and `*Write/channel*` URLs after joining a room: the game must still play.
- **Listen after the server confirms:** a query the rules only allow after a write (everyone's roles once the assassin has picked, the Lady's answer after a pick) is refused if it runs too early. Writes go over HTTPS now, so the room listener only hears of them from the server, but `watchRoom` still waits for `hasPendingWrites` to clear and retries if refused anyway.
- **Avalon's trust trade-off (chosen by the user):** on Spark there are no Cloud Functions, so the host's phone deals the roles, and a player watching Firestore live could match tally changes to markers. The app never shows either; the rules stop the rest (only your own role, no fails from good players, only the assassin assassinates). Real secrecy would need Cloud Functions on Blaze.
- **Rival Wonders** (`/duel`, `src/screens/duel/`) is a two-player duel of ancient wonders, each player on their own phone. It plays as the published two-player duel game, but under **our own names: plain descriptive card names, the real historical wonders, and no card text or art from the original.** The publisher owns the brand, the card names and the art, and the site is public, so keep it that way for any card or game added. `src/games/duel/` is the game as pure TypeScript: `cards.ts` (data), `setup.ts` (the three layouts and a seeded deal), `pay.ts` (cheapest payment) and `state.ts`, a reducer (`apply`) with `replay(seed, players, moves)`; moves the game refuses are skipped, so a tampered client can't steer the other phone. `tests/unit/duel.test.ts` checks each rule and plays hundreds of random games to the end. Its screens use the same icons as Ancient Wonders (`src/screens/duel/CardIcons.tsx`, plus the duel's seven science symbols in `GameIcons.tsx`).
- **Rival Wonders data** is `duels/{code}` (two players, the seed written at the start) and `duels/{code}/moves/{n}`, appended in order by the player making each move (`src/services/duel.ts`, `tests/rules/duel.test.ts`). Same trust trade-off as Avalon: the seed decides the face-down cards, so a player reading the data could learn them early; the app shows a card only once it's uncovered.
- **Ancient Wonders** (`/wonders`, `src/screens/wonders/`) is the 3–7 player game of ancient wonders, under the same naming rule as Rival Wonders (none of the original's card names; the seven real wonders, both board sides). `src/games/wonders/` is pure TypeScript: `cards.ts` (cards with their player-count marks, guilds, boards A and B), `setup.ts` (a seeded deal), `pay.ts` (the cheapest buy from either neighbour), `state.ts` (simultaneous picks that resolve once every seat has picked; hands pass left, right in Age II; battles each age; scoring) and `bot.ts`. `tests/unit/wonders.test.ts` checks the decks hold exactly 7 cards a player for 3 to 7 players, each rule, and whole games with bots and random moves. Its screen draws costs and effects as icons (`src/components/GameIcons.tsx`: coins, points, shields, resources, science; `src/screens/wonders/CardIcons.tsx`), with a folded key at the bottom; icon colours are `--icon-*` tokens.
- **Ancient Wonders data and bots:** `wonders/{code}` (seats in table order, clockwise: your left neighbour is the next seat; `sides`; the seed) and `wonders/{code}/moves/{n}`, appended in order. Phones pick at the same time, so `sendMove` retries the next number when another phone took it. Bots are seats `bot:1`–`bot:6`; only the host may write their moves, and the host's phone plays them (`botMove`), so a game with bots needs the host's phone open. Same trust trade-off: a pick is readable in the data before the reveal; the app shows only who has picked.
- **Island Settlers** (`/isle`, `src/screens/isle/`) is the hex-island trading game for 3–4 phones, under the same naming rule as the Wonders games: **never the publisher's name, card text or art**; plain words (brick, lumber, wool, grain, ore; knight, Road building, Plenty, Monopoly). `src/games/isle/` is pure TypeScript: `board.ts` (19 hexes, 54 corners, 72 sides, 9 harbours, all fixed; corner offsets written out, since trig is banned by the purity test), `setup.ts` (seeded lands, numbers with no 6/8 side by side, harbours, the development deck), `state.ts` (the reducer, `replay`, longest road and largest army) and `bot.ts`. The map (`IslandMap.tsx`) draws only the spots you can use now as gold targets. `tests/unit/isle.test.ts` checks each rule and plays hundreds of all-bot games to a winner.
- **Island Settlers data and trust:** `isles/{code}` (seats in turn order, the seed) and `isles/{code}/moves/{n}`, appended in order (`src/services/isle.ts`, `tests/rules/isle.test.ts`). Discards after a 7 and answers to a trade offer come from several phones at once, so `sendMove` retries the next number. Bots are `bot:N` seats played by the host's phone; they trade only with the bank and turn down offers. **The dice and the robber's steal come from the seed (chosen by the user)**, so a tampered phone can't pick its roll, but a player reading the data could predict rolls; the app never shows them early.
- **Hero Gambit** (`/hero`, `src/screens/hero/`) is **the main game (the user's design)**: everyone has one hero that grows. Fights are turn-based 1v1, one skill a turn, from a seeded coin flip, to 0 HP: against a **ladder of 20 bot creatures** (`/hero/fight`, a boss every fifth) or a friend online (`/hero/online`, `/hero/:code`). Stats are HP, DEF (`dmg × 100 / (100 + DEF)`), Crit and Crit damage. The three skills: **Stopwatch** (a seeded target from 1.00 to 10.00 s in hundredths, like 4.37 (the user's choice); Start, then Stop; the clock hides after 1 s; damage scales with how close, within 50 ms is Perfect and a sure crit; once started there's no going back for another try), **Roulette** (pick 0–36; one ball a level on a 37-slot wheel; any ball on your number is an instant kill, otherwise a punch) and **Poker** (the user's design: the thirteen cards 2 to A show face up, turn over and shuffle, then you pick one (`{skill: 'poker', pick}`) and the fight waits (`state.pending`) while **the other side picks theirs** (`{skill: 'card', pick}`, any card but yours; a friend picks on their own phone, a bot or arena hero through `botMove`); only then does the turn play out, as the attacker's, with the deck's order from the turn's seed; ace high; higher does 100 as a crit, lower nothing). **Skill points** come only from beating a bot level the first time (1, or 3 for a boss; `rewardFor`, `pointsFor`; the user said rewards are all points for now and will be decided later), spent in **one tree** of seven nodes up to 10 each (the three skills, Roulette needing Stopwatch 2 and Poker needing Roulette 2, plus the four stats), with a free Reset. **The bots are creatures, not heroes (the user's design):** they have no skills, only a kit of attacks (`monsters.ts`: plain hits, a sure jab, a heavy slam that can miss, drain, and attacks that cast **effects** lasting a few turns: burn, weakened hits, smoke that hides your next stopwatch clock at once, guard up, wind-up for one stronger hit); bosses add a finisher and are enraged below half HP. Five families of our own (clocks, coins, cards, dice, wheels), each family naming the attacks its own way. Effects apply to every move, but only creatures cast them, so hero-against-hero fights (friends, the arena) never see one (a test pins their own hash). `src/games/hero/` is pure TypeScript: `stats.ts` (the tree and every tunable number), `skills.ts` (`resolve`; each turn's luck from streams named `${seed}:turn:${n}:…`), `monsters.ts` (the attacks, effects and the creature brain), `state.ts` (`apply` with effects, `replay`, `HERO_VERSION`) and `bots.ts` (`BOT_LEVELS` with each creature's stats and kit, `botFighter`, `sparringTree` for the arena's stand-in hero, and `botMove`, which plays a creature from its kit or a hero's skills with stops within `spread` ms of the target). The stopwatch's time is measured in the screen (`performance.now()`) and passed in the move. `tests/unit/hero.test.ts` checks each skill, attack and effect, replays a golden hash (bump it with `HERO_VERSION` when fights would replay differently) and plays every bot level with a hero holding the points from the levels before (each won over 30% of the time, no boss over 95%). **The fight screen (`Fight.tsx`, the same for bots, the arena and friends) is laid out like a handheld creature battle (the user's reference), in our own art and palette:** the foe's box top left and the foe on a platform top right, your hero from behind bottom left and your box (with HP numbers and effect chips) bottom right, and a text box under the thumb that tells each turn line by line ("Foe Pocket Watch used Tick Strike!"; a tap skips) and then becomes the 2×2 menu (three skills and the log). Attackers lunge, the struck flash, HP bars drain, the loser sinks. Roulette spins a real single-zero wheel over the field (SVG, Web Animations), each ball dropping into its pocket; poker flips the two cards there. `turnShowMs` is how long a turn takes to tell: the bot waits it out before moving, and so does the result panel. The sprites are inline SVG in `Sprites.tsx`, coloured by `--mon-*`, `--hero-*`, `--battle-*` and `--spin-*` tokens. **Every creature's attacks are animated** (`AttackFx.tsx`, `--fx-*` tokens; normal creatures play a smaller version without the field shake): slashes, a falling slam with shockwaves, flames, sound rings, smoke, a shield, a charge-up with sparks, a drain flowing back to the boss, and each family's finisher (a giant clock sweeping to midnight, a fan of thrown cards, a spinning wheel blade; coin rain and a falling die are ready for coin and dice bosses), ending in a flash; slams and finishers shake the field, and an enraged boss glows red. A creature's hit lands at `attackImpactMs` (a little later for a boss, 1.8 s for a finisher), which the text box, the bot's wait and the result panel all follow. The screen only plays a turn that arrives on its own, so two moves landing at once skip the show.
- **Hero Gambit data:** `src/heroStore.ts` keeps the hero and the bot fight in progress (its seed, your tree at the start, every move) in localStorage (`game:hero`), then syncs to **`heroes/{uid}`** (`cleared`, `tree`; owner only). `firestore.rules` caps the tree by `heroPoints(cleared)` (a copy of `pointsFor`; `rulesSync.test.ts` compares them) and lets `cleared` rise by one a write, so levels beaten offline are written step by step; a phone behind the server takes the server's hero. Friend fights are `heroDuels/{code}` (like `duels`, plus `fighters`: each player's tree, which the rules check equals their own hero doc, so the hero is synced first, `heroReady()`) and `heroDuels/{code}/moves/{n}` (`src/services/hero.ts`, `tests/rules/hero.test.ts`). Friend fights give no points. The screen shows "Sending your move…" until the server has it (see **Rooms survive a stalled stream**). **Trust trade-off**, as in the party games: the rules can't watch a fight, so a tampered phone could claim a bot win or a Perfect stop, and a player reading the data could predict balls and cards from the seed; the app never shows them early.
- **Your hero's look, costumes and Summon (the user's design):** a blocky, build-it-yourself figure (`src/games/hero/look.ts`: skin tone, face, hair and its colour, hat, shirt and its colour, pants and their colour, an extra; drawn by `Avatar.tsx`, front and back) that everyone gets free, plus **meme costumes** worn over it (`costumes.ts`, drawn in `Costumes.tsx`): Italian brainrot only (Tung Tung Tung Sahur, Tralalero Tralala, Bombardiro Crocodilo and twelve more), memes nobody owns, always our own drawings, never anyone's picture; and "like Roblox" is a style reference only, never a name or asset. **Costumes give a small stat bonus** (the user's choice), capped by rarity (`BONUS_CAP`, tested), through `statsOf(tree, bonus)`; a fighter carries `costume`, and saved fights keep the one worn when they began. **Summon** (`gacha.ts`, `/hero/summon`) pulls from the pool: Legendary 2%, Epic 8%, Rare 30% (costumes), Common 60% (rarer hats, extras and armour); a Legendary at the latest every 50th pull; ten pulls for 900 gems hold a Rare or better; a repeat becomes gems. **Gems** come from fights (`gemsFor`: 50 for a new level, 150 for a new boss, 10 or 25 for a rematch, 20 for an arena win, 5 for a loss) and there's one free pull a day (the phone's own date). The Wardrobe (`/hero/wardrobe`) shows each choice on your hero; Summon parts stay greyed until owned. **Data:** `src/wardrobeStore.ts` (localStorage `game:wardrobe`) syncs to **`wardrobes/{uid}`** (owner only; the first time a phone meets the server's wardrobe the two are merged); `heroes/{uid}` carries `look` and `costume` (the rules check the costume is in the wardrobe), and so do `arena/{uid}` and `heroDuels/{code}.looks` (both must equal the hero doc), so opponents see you as you are and fight your costume's bonus. **Trust trade-off**: Summon runs on the phone, so a tampered phone could give itself gems or costumes; the rules check only the shape, and the bonus is small (`tests/rules/wardrobe.test.ts`, `tests/unit/wardrobe.test.ts`; `rulesSync.test.ts` compares the catalogue sizes and item list).
- **Hero Gambit arena** (`/hero/arena`, `Arena.tsx`, `ArenaFight.tsx`; **async PvP, the user's choice**): once bot level 5 is beaten, you fight other players' heroes, each a snapshot played by the bot brain on your phone (`botMove` with `DEFENDER_SPREAD`), so no one has to be online; fights save and resume like bot fights, and giving up counts as a loss. Only the attacker's rating moves: a win gains `20 + (theirs − mine) / 25` clamped to 5–35, a loss costs 40 minus that (`ratingChange` in `src/games/hero/arena.ts`, with `tierOf`: Bronze, Silver 1100, Gold 1250, Platinum 1400, Diamond 1600). No skill points (the user's choice: the tree stays tied to the bot ladder). Opponents are found by rating, ±150 then ±400 then anyone (`findOpponents`, single-field queries, no index); with none, a bot-ladder hero stands in as "Sparring". **Data:** `arena/{uid}` (`name`, `tree`, `rating`, `wins`, `losses`, `lastFightAt`), readable by anyone signed in, written only by its owner: joining needs `heroes/{uid}.cleared ≥ arenaUnlock()` and the hero's own tree and name; a refresh keeps tree and name equal to the hero doc and player; a result changes one of wins/losses by one and the rating by 5–35 the matching way, at least 10 s after the last (`tests/rules/arena.test.ts`; `rulesSync.test.ts` checks the copied numbers). Results count on the phone at once and `heroStore.sync()` writes them in order 10.5 s apart; the Ranks tab has an Arena board (top 50). Trust trade-off as elsewhere: a tampered phone can claim wins, but only 35 points per 10 s.
- **Stick Brawl** (`/brawl`, `src/screens/brawl/`; it was Sky Brawl, and the route and `game:brawl` key kept that name) is the one real-time game: a stickman shooter-brawler against 1–3 bots on one phone, offline, under **our own names** (never the published stickman or platform-fighter games' names, characters or art; guns are plain nouns). **Reconceived by the user:** everyone is the same stick figure with **100 HP**, and a match has **rules the player picks** (`Rules` in the match, a Rules sheet on the front door, the host's choice online, written to the room at start and checked by `isBrawlRules` in `firestore.rules`): **score**, rounds where the last one standing gets a point, first to 3/5/7/10; or **timed**, 3/4/5 minutes where a kill is +2 and a death −3 (`score`), everyone respawns after 2 s at the spawn furthest from the others, the stage changes each minute, and a tie at the end goes to sudden death (`overtime`: the first to lead alone wins). **Every stage is closed in** (the user's choice): `stages.ts` adds side walls that rise far above the screen and a floor within a double jump of the main ground (`walls`, `floor`, platforms marked `frame`), and the bottoms of gaps are spike beds (`pits`); the **top is open**, so a fighter launched up just falls back in (only the sides and bottom of the blast zone still count, the Cave's ceiling is the one closed top). There are **sixteen stages** (`src/games/brawl/stages.ts`, played in a seeded order): Rooftops (plain), Lifts (moving platforms, pure functions of the frame, riders carried), Lava (burns and bounces, bounce pads), Spikes, Crumble (blocks crack a second after they're stood on, fall, come back), Gusts (seeded wind with a warning), Conveyor (platform `belt`s carrying everyone toward a gap), Ice Rink (`slippery` ground), Moon (a stage `gravity` of 24, not 50), Sawmill (saw blades riding triangle waves like movers), Trampolines (bounce pads), Columns (pillars; bots jump the gaps to reach someone standing across), Cave (a low solid ceiling), Minefield (`mines` that blow when stepped on and re-arm, timers in `match.mines`), Laser Grid (beams that warn, then fire, on a cycle: `beamAt`) and Anvil Rain (seeded anvils from the sky with a shadow, projectiles with owner -1, so `applyHit` has no attacker to freeze). Fighters start bare-handed; weapons (`weapons.ts`: sword, hammer, spear, axe, scythe, pistol, burst rifle, shotgun, sniper, rocket launcher, bow, grenades, knives, boomerang, frost staff, and the silly ones the user asked for: rubber chicken (tiny damage, huge push), baguette, bananas (peels that lie where they land and trip anyone, the thrower too: a projectile `trap`), bubble gun (floats up and lifts: an `angle` override), leaf blower (no damage, a fan of shoves), flamethrower, minigun, harpoon gun (`pull`s them in), ray gun (`ricochet`s off walls), black hole (`vortex`: settles and slides everyone toward it), wet fish (a dazing slap) and spring glove (long-reach punch)) drop in from the seed, are picked up by touch, and carry **ammo** (shots or swings); empty, the next Attack **throws** it. Fast shots move in sub-steps of at most 16 px so they can't skip a body; a boomerang steers home with `Math.sqrt`, which is exact everywhere. `src/games/brawl/` is pure TypeScript: `state.ts`'s `step(match, inputs)` runs a frame, rounds included (`wins`, `between`, `startRound`), in **whole numbers only**, so the same inputs make the same fight; plus `bot.ts` (seeded; fetches weapons, lines up shots on eight directions or moves level, closes in, rolls, recovers to the stage's `safe` ground) and `controls.ts`. Bump `BRAWL_VERSION` and the golden hash in `tests/unit/brawl.test.ts` when the engine changes. **Two thumbs, sideways (the user's scheme; the one game that breaks the one-thumb, portrait brief):** a floating joystick under the left thumb (run; down to fall fast or drop through a ledge; it aims, and centred the engine aims at the nearest fighter) and four buttons under the right: Jump, Attack, Heavy, Dodge. **Heavy is held** (`SKILL2` is a held bit, `HELD` in `input.ts`, which rollback repeats when guessing): it charges up to `MAX_CHARGE` (1 s, walking slowly) and on release is a **kick** (stick centred; up to ×2) or a **throw** of what's held (stick pushed; up to ×2); let go straight up in the air, it's a once-per-jump leap. A hit or a dodge drops the charge. **Dodge** is only a dodge (the ice floor was removed at the user's request): it rolls on the ground and, in the air, is a short untouchable **air dash** along the stick (a hover with it centred), once per jump. `Arena.tsx` fills the screen with HP bars, round pips and ammo, shows a banner between rounds, pauses to a two-button panel (Resume, Restart: nothing to scroll, since the stage blocks touch scrolling), and on an upright screen (the user's phone stays locked to portrait) turns the whole stage a quarter with CSS and maps touches back (`point()`); it blocks pinch and double-tap zoom itself (iOS ignores `touch-action: none`). `draw.ts` draws stick figures (posed, limp when out), weapons, tracers, each stage and its hazard, with colours from `--brawl-*` tokens; bots go by their colour, you're always gold. A fight is saved in `game:brawl` about once a second and on leaving; a finished one never is.
- **Stick Brawl online** (`/brawl/online`, `/brawl/:code`, `BrawlRoom.tsx`) is 1v1 between two phones over a **WebRTC data channel** (unordered, never resent). Firestore holds only `brawls/{code}` (players, seed) and the handshake, `brawls/{code}/signals/offer` and `/answer`: the whole SDP in one write each, numbered `offer-1`… for "Try again" (`src/services/brawl.ts`, `tests/rules/brawl.test.ts`). The fight never touches Firestore. **Free STUN only, no relay (chosen by the user)**, so some pairs of networks (two mobile carriers) can't connect; the app says so after 10 s and offers bots. Each phone runs the same `step()` with **rollback** (`src/games/brawl/rollback.ts`: 2 frames of input delay, the other player guessed as still holding their direction, replays of up to 10 frames, stalls beyond that, a skipped frame now and then to stay level, and a `hashState` swap every 60 frames that ends the fight if the phones disagree); `tests/unit/brawlNet.test.ts` runs two sessions over a lossy, jittery fake link and checks they match the true fight. Messages (`net.ts`) carry a `round`, so a rematch (a new seed sent by the host over the channel) ignores the last fight's stragglers. `Arena.tsx` draws either kind of fight from a `Driver`; your own fighter is always gold. Same trust trade-off as the party games: a tampered phone could send inputs no thumb made. In dev, React runs effects twice, so `connect()` checks its abort signal before every write.
- **Rules check shape, not answers:** `firestore.rules` copies `NONOGRAM_VERSION` and `sizeFor()`; `tests/unit/rulesSync.test.ts` fails if they drift.

## Constraints

- **Catching cheats:** the rules can't make a puzzle, so `npm run audit` (`scripts/audit.ts`) remakes each level and day and reports saved grids that don't match the clues. It's read-only; run it by hand against production with `AUDIT_PROJECT_ID=<id>`.
- **Spark plan:** no Cloud Functions, no Cloud Storage. `firestore.rules` is the only server-side validation, so every client write needs a matching rule and a test in `tests/rules/`.
- **Old data stays and is closed.** Neon Flap's data (`users/*`, `leaderboards/*`, `items/*`) and the auto-battler's (`runs/*`, `puzzles/*`, `rankings/*`, `dailyRankings/*`), plus this game's removed daily puzzle (`dailySolves/*`), are left in Firestore, because deleting them would only spend quota. The rules deny all of it except a player reading their own `users/{uid}`, which the app does once to carry their name over. Auto-battler `players` docs keep their extra run fields; renaming still works. `tests/rules/legacy.test.ts` and `tests/rules/solves.test.ts` cover this.
- **Show only what's needed now** (the user found the screens too complicated). A game screen centres on the decision in front of you, with one line about you. Everything else (other players, full city details, history, options, rules) folds into a one-line `SummaryRow` that opens a `Sheet` (`src/components/`), so it stays one tap away. Party games share `GameHome` and `Lobby` (`src/components/RoomSetup.tsx`), with lobby options under Options. The map shows its in-progress banner only for a room whose game is still on (`lastRoom()` in `src/lastPage.ts`; each room calls `forgetRoom` when its game ends).
- **Train-friendly is the brief:** keep everything reachable with one thumb (controls at the bottom), make nothing depend on sound, add no timers or fail states, and save every change at once.
- **One dark palette of our own** (it used to match the sibling repo `../invest`; it no longer does). It's dark only, with no light theme or toggle. Surfaces lift by luminance (`--bg` → `--surface` → `--surface-2`), a soft shadow and a faint top highlight; a gold glow sits at the top of the page. The one accent is gold (`--accent`, `--accent-grad`): filled squares and primary actions, which are solid gold with dark text, one per screen. The world map's zones each have a colour of their own (`--zone-keep` blue, `--zone-tower` violet, `--zone-arena` ember, with `-soft`/`-glow`), used only for their landmark, badge and banner; the map's art uses `--map-*` tokens. Rounded, pressable surfaces scale slightly when pressed. Text is Inter, bundled from `@fontsource-variable/inter` so it's cached offline, and small labels are 10px uppercase. Colours are written only in `src/index.css`'s `:root` block; everything else uses `var()`. `--bg` (`#0a0b0d`) is repeated in `index.html`'s boot styles, the manifest colours and the icons in `public/`, so change them together.
- **Never rename the storage keys `game:nonogram`, `game:library`, `game:lastPage`, `game:hero` or `game:wardrobe`** (`game:library` now holds knowledge topics and saved cards, and kept its name from when it also held book highlights; `game:hero` holds the hero, its fights and the arena queue; `game:wardrobe` your look, costumes, gems and Summon's pity count). A new name would wipe them on every device. Old saves carry fields from removed features (the daily puzzle, highlights); the stores ignore them.
- **Hosting cache headers** in `firebase.json` match the *requested* path, not the file served. The no-cache rules therefore use `/` and `/*` (the app's routes, which all serve `index.html`); `/assets/**` has two segments, so hashed assets keep their immutable caching. Without this, a deploy can be masked for an hour by a cached page.
- After a deploy, the first visit is served from the offline cache and runs the **previous** version, which may not match current rules. `src/main.tsx` swaps in the new build once the player is off the puzzle (`/`) or the app is in the background, and Settings (⋯ → Settings) has "Reload the latest version" (`src/reload.ts`), which clears the service worker and caches.
