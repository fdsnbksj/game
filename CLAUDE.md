# CLAUDE.md

**a game**: a mobile web nonogram game for a train ride with a book: small logic puzzles to play between chapters, each followed by one short, useful idea (psychology, software engineering, philosophy, productivity). Tap squares to fill them so every row and column matches its clue numbers. It's played with one thumb and no sound, with no clock or way to lose, and every tap is saved, so it can be put down at any moment, even offline. Levels are endless (5×5 growing to 10×10) and ranked. React handles the screens and Firebase the free-plan backend (Auth, Firestore, Hosting). Setup and layout are in `README.md`. It replaced an auto-battler, which had replaced **Neon Flap**; both left data in Firestore that is now closed (see Constraints).

## Git and deploy

- **Only the `main` branch.** Commit directly to `main`. Don't create branches or pull requests.
- **Every push to `main` deploys to production** via `.github/workflows/deploy.yml`: unit tests → build → Firestore rules tests → deploy Hosting and Firestore rules → deploy Firestore indexes. Push right after each commit so every commit is deployed.
- The index step may fail if the deploy account can't create indexes; it's allowed to, so the site still deploys, and the level rankings fail to load until the index exists. If it fails, run `npm run deploy` logged in as a project owner.
- Auth settings in `firebase.json` (anonymous sign-in) are **not** deployed by the workflow, because the deploy account lacks those permissions. After changing them, run `npm run deploy` logged in as a project owner.
- A failing build, unit test or rules test stops the deploy, so run `npm run build`, `npm run test:unit` and `npm run test:rules` before committing.
- Never commit secrets. The Firebase web config in `.env.production` is public by design. The deploy service account key lives only in the `FIREBASE_SERVICE_ACCOUNT` GitHub secret.
- The production Firebase project ID is the `default` entry in `.firebaserc`. Local development always uses the `demo-game` emulator project.

## Commands

```sh
npm run emulators   # Auth + Firestore emulators (needs Java 21: /opt/homebrew/opt/openjdk@21/bin on PATH)
npm run dev         # Vite dev server, reachable from a phone on the LAN
npm run build       # type-check + production build
npm run audit       # checks saved solves against their puzzles
npm run set-level -- --name <player> --level <n> [--write]   # admin: set a ladder's level (emulator unless PROJECT_ID=<id>)
npm run test:unit   # puzzle logic tests, no emulator needed
npm run test:rules  # Firestore rules tests (starts its own emulator; stop `npm run emulators` first)
```

## How the game fits together

- **`src/nonogram/` is the whole puzzle as pure TypeScript**: clues, a line solver, the generator and the play reducer. No DOM, React, Firebase, `Math.random` or `Date`; `tests/unit/purity.test.ts` enforces it. Every random choice comes from a named seeded stream (`src/nonogram/rng.ts`), so a level or day gives the same puzzle on every device.
- **Every puzzle is solvable by logic alone.** `nonogram(level)` draws random pictures until the line solver (`solve()`) settles every cell from the clues, which also proves the answer is unique. Each try is a little denser, and a full grid always settles, so it always ends. Changing the generator or `sizeFor()` changes every puzzle: bump `NONOGRAM_VERSION` and update the golden hash in `tests/unit/nonogram.test.ts`. A new version starts a new ladder (`ladders/{uid}_{version}`), and localStorage progress restarts with it.
- **Play is checked against the clues, not the stored answer** (`isSolved()`). Crosses are only notes. A stroke (a tap, or a drag locked to one row or column) is one undo step, and nothing is committed until the finger lifts (`src/components/Board.tsx`).
- **Home is a game centre (the user's choices, 2026-10-15: a searchable list of every game, then "more cool, like a game centre"; before that Hero Gambit only, and before that a drawn world map with zones, since removed).** `/` is `src/screens/world/GameList.tsx`, on its own (no `WorldShell`): "Hi, name" over a big "Game Centre" title with a round avatar opening `/account`, a pill search (name and tagline; while searching only results show), a Continue card for a room still on (`lastRoom()`), a featured card for Hero Gambit (a blue-to-violet sweep, two bobbing stick figures, VS, Play), then every game as a two-column tile (a block in the game's `--game-*` colour with its white emblem, name, tagline, players or the nonogram level). Its colours are `--hub-*` tokens. Every game is in `src/screens/world/games.ts`, the one list (`tests/unit/games.test.ts` checks each is listed once and its route exists). `WorldShell` (a top bar with your name) is now only around `/account`, `/saved` and `/ranks`. **Front doors match** (the user's ask): each opens with a `GameBanner` (`src/screens/world/GameBanner.tsx`), a big card in the game's colour with its white emblem (Hero Gambit's: the two stick figures and VS, on the featured sweep), name, line and players, and the door's buttons are pills with the main one in the blue-to-violet sweep (`.front-door`). **Lobbies and rooms match too:** a game's pages pass `game` to `Page`, which adds `game-room tile-<id>`: the title becomes a pill with a dot in the game's colour, buttons are pills with the main one in the sweep (`.choice-row`, `.skill-button` and `.wonder-button` keep their own shapes), the lobby's code sits on a banner in the game's colour, and the turn box of Ancient Wonders (`.duel-status`, named after the removed Rival Wonders) is a white card with a colour stripe that turns into a colour banner on your move. Avalon's table matches (the user's ask): the oval is a deep sweep from Avalon's blue (`--avalon-table-*`) with white text, seats are white cards (team tinted, picked filled with the sweep, the leader ringed), marks are pills, quests fill in the sweep (current), green (won) or red (lost), and the role card is the sweep until held, then green or red. In Hero Gambit's fight the field has a pale sky and each skill button is its own colour (`--skill-*`). Every game's front door goes back to `/`; Hero Gambit's front door (host, join, one phone, rules) is `/hero` (`src/screens/hero/Home.tsx`), and its rooms go back there. Nonograms live at `/nonograms` (`Play.tsx`), with a ⋯ menu to Saved cards (`/saved`), Rankings (`/ranks`) and Settings, which go back where they came from (`cameFrom`). `restoreLastPage` reopens any game's page. Other screens stay plain: white `.group` cards, no frames or ribbons.
- **Accounts** (`src/services/account.ts`, `/account`): everyone starts as an anonymous guest (`startSession`). Creating an account links an email and password to that same user (`linkWithCredential`), so the uid, name and ladder stay. Signing in to another account switches uid; `nonogramStore.claim()` then drops the device's ladder if it belonged to someone else, and `catchUp` loads the account's level. Signing out makes a new guest. The Email/Password provider is enabled in `firebase.json`, which the workflow doesn't deploy (see above).
- **Reopens where it was left.** The installed app always starts at `/`, so `src/lastPage.ts` saves every route to localStorage (`game:lastPage`) and, when the app opens at `/`, `restoreLastPage()` (in `main.tsx`, before the router) replaces it with the saved page if it's one of the app's own. A room that's gone or under way without this phone shows a way back to the games.
- **Offline first.** `src/nonogramStore.ts` (zustand) holds the plays in progress, the ladder level, solved days and settings, and saves every change to localStorage (`game:nonogram`). The app never waits for Firebase: `startSession()` signs in in the background and retries when the connection returns.
- **Online solves:** a solve is counted locally first, then queued and written in order at least 3 s apart, as the rules require, once there's a session. A network error leaves it queued. If the rules refuse a level, the ladder carries on unranked on that device.
- **The ladder** is `ladders/{uid}_{NONOGRAM_VERSION}`: the highest level solved and each level's grid (one `0`/`1` string, row by row). The first write creates the doc at level 1. Once a session, before writing, `sync()` reads the player's ladder and `catchUp()` moves the device up to it if the server is ahead: a new phone, cleared storage, or a level set with `scripts/setLevel.ts`, which files every level's real answer so the audit stays clean.
- **A knowledge card after every puzzle:** one short idea from psychology, software engineering, philosophy or productivity, with a "Try this" line (`src/learn/knowledge.ts`, about 40 per topic; a new topic starts switched on for existing players via `offered` in `src/knowledgeStore.ts`). `pickKnowledge()` shows every card of the chosen topics before any repeats. Cards are written in our own words and name their source; hedge where the research is weaker than the popular version. `tests/unit/learn.test.ts` caps their length so they fit on a phone. Topics and saved cards live in localStorage (`src/knowledgeStore.ts`), never Firestore.
- **Avalon** (`/avalon`, `src/screens/avalon/`) is played at one table, each player on their own phone; the talking happens out loud. `src/games/avalon/` is the game as pure TypeScript: `rules.ts` (published tables), `deal.ts` (roles and night knowledge) and `state.ts`, whose `derive()` works out phase, leader, quests and winner from the documents, so every phone reaches the same state and no one has to advance the game. `src/services/avalon.ts` writes each player's own actions and follows a room live (`watchRoom`).
- **Avalon data** is `rooms/{code}` with subcollections `secrets` (each player's role, readable only by them until the game is over), `proposals`, `votes` and `quests` (tallies only: a card is a marker holding nothing, written with the tally going up by one, so no document says who played a fail). `firestore.rules` checks each write; `tests/rules/avalon.test.ts` covers them.
- **Avalon's table and the Lady of the Lake:** `playerIds` is the seating order, clockwise; the host arranges it in the lobby so the lead passes the way people really sit, and `TableView.tsx` draws the seats around an oval (leader, next, team, votes, Lady; tap to pick). While a player holds their role card, their night knowledge is marked on the seats too (Merlin's evil, Percival's Merlin-or-Morgana pair, evil's fellow evil) with a legend under the table; it all hides on release, like the card. The Lady is optional: after quests 2–4 her holder examines someone (`lady/{after}`, public) and passes her on. The examined player's own phone files their loyalty (`ladyResults/{after}`), which the rules check against their role and let only the holder read. The Lady's rules avoid `? :`: the emulator crashes on those conditionals instead of denying, and the write just hangs.
- **Rooms survive a stalled stream (every room game: Avalon, Ancient Wonders, Hero Gambit, Bluff Table).** On phones the main SDK's stream can wedge after the app has been in the background (switching to a chat to share the code), so listeners stop hearing changes and a write through it can sit pending forever: a real bug left two phones each waiting on the other. So room writes go over plain HTTPS (`dbRest`, Firestore Lite, in `src/firebase.ts`; each lands or fails then and there), and `src/services/resilient.ts` follows rooms: `keepFresh` remakes the listeners when the page comes back, the connection returns or one fails, and reads over HTTPS every few seconds (only while the page is showing) and right after each write of ours (`poke`). `followRoom` does this for a room plus its numbered moves (kept by number, so a move counts once however it arrives); Avalon checks counts of its collections every 10 s and reads again only what differs, to stay cheap on Spark's read quota. To test it, block a headless browser's `*Listen/channel*` and `*Write/channel*` URLs after joining a room: the game must still play.
- **Open rooms and empty rooms (the user's asks, 2026-10-18):** every party game's home (`GameHome`, and Hero Gambit's own) lists the rooms still in their lobby under the buttons, with a Refresh button (`OpenRooms` in `RoomSetup.tsx`, `openRooms()` in `src/services/lobbies.ts`; loaded on opening, a tap joins; Hero Gambit lists only rooms on its own `HERO_VERSION`). A player with a room's page open, waiting or playing, sends a heartbeat (`seenAt`, `useRoomHeartbeat`) on opening, every minute while the page shows, and when it comes back. **A lobby nobody has been in for 10 minutes, or a started or finished game nobody has been in for 30, is deleted** by the next phone that opens that game's home (Spark has no scheduled jobs). Lobbies are dropped from the list as it loads; `clearAbandoned` deletes up to 3 abandoned games a visit, oldest first, everything under each room (moves; Avalon's secrets, proposals, votes, quests and their cards, lady, ladyResults) and then the room, so a half-done clear finishes next time. The rules (`isHeartbeat`, `isAbandonedLobby`, `isAbandonedGame`, by `seenAt`, else `createdAt`) let anyone read and delete a room that stale and what's under it; `tests/rules/lobbies.test.ts` covers all five collections. So a phone put away for over 30 minutes mid-game (both players' phones, or every player's) comes back to "room gone": the user chose that. 10 minutes for a lobby, not less, because a host sharing the code from a chat app sends no heartbeat.
- **Listen after the server confirms:** a query the rules only allow after a write (everyone's roles once the assassin has picked, the Lady's answer after a pick) is refused if it runs too early. Writes go over HTTPS now, so the room listener only hears of them from the server, but `watchRoom` still waits for `hasPendingWrites` to clear and retries if refused anyway.
- **Avalon's trust trade-off (chosen by the user):** on Spark there are no Cloud Functions, so the host's phone deals the roles, and a player watching Firestore live could match tally changes to markers. The app never shows either; the rules stop the rest (only your own role, no fails from good players, only the assassin assassinates). Real secrecy would need Cloud Functions on Blaze.
- **Rival Wonders was removed (the user's ask, 2026-10-17).** It was a two-player duel of ancient wonders at `/duel`; its code is in git history. Its rooms (`duels/*` and their moves) stay in Firestore, closed (see Constraints).
- **Ancient Wonders** (`/wonders`, `src/screens/wonders/`) is the 3–7 player game of ancient wonders, under **our own names: plain descriptive card names, the real historical wonders (both board sides), and no card text or art from the original.** The publisher owns the brand, the card names and the art, and the site is public, so keep it that way for any card or game added. `src/games/wonders/` is pure TypeScript: `cards.ts` (cards with their player-count marks, guilds, boards A and B), `setup.ts` (a seeded deal), `pay.ts` (the cheapest buy from either neighbour), `state.ts` (simultaneous picks that resolve once every seat has picked; hands pass left, right in Age II; battles each age; scoring) and `bot.ts`. `tests/unit/wonders.test.ts` checks the decks hold exactly 7 cards a player for 3 to 7 players, each rule, and whole games with bots and random moves. Its screen draws costs and effects as icons (`src/components/GameIcons.tsx`: coins, points, shields, resources, science; `src/screens/wonders/CardIcons.tsx`), with a folded key at the bottom; icon colours are `--icon-*` tokens. **The table always shows (the user's ask):** your board in the middle, drawn like a real one (a framed sandstone plate, the wonder as our own plain silhouette against the sky (`WonderArt.tsx`), its starting resource in the corner, its stages as slots along the bottom, filled with a face-down card once built; colours are `--board-*` tokens; classes are `wboard-*`, since `.board` is the nonogram's grid) and down each side that neighbour's board in small (their wonder and a slot per stage, filled once built) over what they sell you, outlined when it's 1 coin (`Table.tsx`; a side opens their full board). `WonderBoard` is the one board drawing, for you, a neighbour's sheet and the (i) sheet of every player's board. The hand is fanned out like cards held in real life: press and hold one and it comes up big to read (slide along the fan to read the others, let go to put it back); a quick tap opens it big like a trading card game's viewer (`CardViewer.tsx`): it zooms out of the hand, tilts with a sheen under the finger, swipes to the next card, and the build, wonder and discard buttons sit under the thumb. The fan is fixed to the bottom of the screen (`.fan-dock`, with a `.fan-space` in the page so nothing hides under it). A card you can build free through a chain glows gold (`--chain-glow`) and its big view says which of your cards makes it free, and which later cards it would make free (`chainsTo`, the user's ask). The big card is sized to the room left above its buttons (a size container on `.viewer-stage`), never a guess at their height: a real bug on Android Chrome, whose larger text made the buttons taller so the card covered Build and swallowed its taps. The (i) in the status box opens every player's city, round the table from you. **The wonder games' icons are emoji (the user's choice, 2026-10-16):** `EMOJI` in `GameIcons.tsx` covers coins, points, shields, resources and science.
- **Ancient Wonders data and bots:** `wonders/{code}` (seats in table order, clockwise: your left neighbour is the next seat; `sides`; the seed) and `wonders/{code}/moves/{n}`, appended in order. Phones pick at the same time, so `sendMove` retries the next number when another phone took it. Bots are seats `bot:1`–`bot:6`; only the host may write their moves, and the host's phone plays them (`botMove`), so a game with bots needs the host's phone open. Same trust trade-off as Avalon: a pick is readable in the data before the reveal; the app shows only who has picked.
- **Island Settlers was removed (the user's ask, 2026-10-18).** It was the 3–4 player hex-island trading game at `/isle`; its code is in git history. Its rooms (`isles/*` and their moves) stay in Firestore, closed (see Constraints); `tests/rules/legacy.test.ts` covers them.
- **Hero Gambit** (`/hero`, `/hero/:code` and `/hero/local`, `src/screens/hero/`) is **the main game, and only for playing a friend (the user's choice, 2026-10-11: no bots, no skill tree, every hero the same).** Fights are turn-based 1v1, from a seeded coin flip, to 0 HP: between two phones, or **on one phone, the two players taking turns (the user's ask; `LocalFight.tsx`)**: two names, then the same fight screen with `hotseat` (whoever's turn it is plays, everyone goes by name, "Ann's turn." over the skills, both HP numbers shown; Player 1 stands bottom left); nothing goes to Firestore, and the fight is saved to localStorage after every move (`game:heroLocal`, dropped when `HERO_VERSION` changes), with Rematch, New players and Home at the end. Every hero has 200 HP (the user's ask, 2026-10-17; it was 100), DEF 0, Crit 5% and Crit damage 150% (`HERO_TREE`, `HERO_STATS` in `stats.ts`), and all four skills at level 1. Each skill rests a few of your own turns after use (the user's design: Stopwatch 0, I'm Speed 1, Memory 2, Roulette 3; `cooldownOf`, `state.cooldowns`; with all four resting the only move is `{skill: 'rest'}`, "Catch your breath"). **Stopwatch:** a seeded target from 1.00 to 10.00 s in hundredths, like 4.37; Start, then Stop; the clock hides after 1 s; damage scales with how close, and within 50 ms is Perfect and a sure crit. **I'm Speed** (the user's name): Ready, then a light stays red for a seeded 1.50–4.50 s (`speedDelay`) and turns green; the time from green to the tap is the move (`{skill: 'speed', ms}`, measured with `performance.now()`; a tap on red is −1, a miss); 150 ms or faster is a sure crit. **Stopwatch and I'm Speed are contests, like Memory (the user's ask, 2026-10-17):** after the attacker's go the fight waits (`state.pending`) while the defender has theirs on their phone, seeing the attacker's result (`{skill: 'answer', ms}`: the same target, or their own light, `speedDelay(seed, turn, true)`); the attacker's hit lands only if strictly closer or faster (a tie misses), at the attacker's own power. **Roulette:** pick 0–36; one ball; on your number it's an instant kill, otherwise a 30 punch. **Memory** (replaced Poker, the user's ask, 2026-10-18): Ready, then a seeded 20-digit number (`memoryNumber(seed, turn)`, shown in groups of five) for 5 s, then a keypad to type it back; **the first wrong digit ends the go** (it shows red, then the count is sent; Done sends early). The move is the count (`{skill: 'memory', count}`); the fight waits (`state.pending`) while the defender has their own go with their own number (`memoryNumber(seed, turn, true)`, so watching on a shared phone doesn't help; `{skill: 'recall', count}`); strictly more lands 90 (`memoryPower`, Poker's old power), a tie misses, all 20 is a sure crit. `src/games/hero/` is pure TypeScript: `stats.ts` (the one hero and the cooldowns), `skills.ts` (`resolve`, `memoryNumber`; each turn's luck from streams named `${seed}:turn:${n}:…`) and `state.ts` (`apply`, `replay`, `HERO_VERSION`, now 13). `tests/unit/hero.test.ts` checks each skill, the contests' waits, cooldowns, hundreds of random fights to a winner and their replays, and a golden hash (bump it with `HERO_VERSION` when fights would replay differently). **The fight screen (`Fight.tsx`) is plain, laid out like a handheld creature battle, with a big animation for every skill (the user's asks):** in one field box, the other side's name and HP top left and their stick figure top right, your stick figure (bigger) bottom left and your box with HP numbers bottom right, each figure on a flat ellipse of ground (`Stickman.tsx`, an inline SVG whose front arm is its own path). While a turn plays, its skill's show fills the middle of the screen over a light scrim (`.battle-overlay`, fixed, taps go through): a clock face whose hand sweeps to the stop past a red mark at the target (`ClockShow`), a big light that goes red then green and shows the time (`LightShow`), a single-zero wheel that spins while the ball runs the other way into its pocket (`RouletteSpin`, Web Animations), or a row of digit slots for each side filling up to their count, the first miss dark (`MemoryShow`). **Every turn then shows its result (the user's ask, 2026-10-18):** once the show's animation is over (`ANIM_MS`), a white result card under it says what it came to (both sides' scores, closer/faster/more or no damage) and **stays until tapped** (the user's ask, 2026-10-18; a tap anywhere on the overlay; `useShow` stops time at it, `held`/`release`). The overlay lifts just before the hit, when the attacker lunges and throws a punch (`.punch` swings the arm), the struck one is knocked back with a damage number, and the loser falls over. Below, a text box tells the turn in up to two lines, then becomes your four skills as large buttons with one plain hint each (a resting one says how many turns it still rests). **There's no fight log** (the user had it removed: the click that follows a Stop or Tap, which act on pointerdown, landed on its button and opened it), and a tap on the text box skips only after `SKIP_AFTER_MS`, so that same click can't skip the turn it just sent. `ANIM_MS`, the tap, then `AFTER_TAP_MS` + the swing is each turn's length up to the hit; the fight's end panel (`Fight`'s children) shows only once the last turn has been told. The screen only plays a turn that arrives on its own, so two moves landing at once skip the show. `prefers-reduced-motion` cuts the motion.
- **Hero Gambit data:** a fight is `heroDuels/{code}` (`host`, `playerIds`, `names`, `status`, `createdAt`, then `seed`/`startedAt` and `endedAt`, like `duels`) and `heroDuels/{code}/moves/{n}`, appended in order (`src/services/hero.ts`, `tests/rules/hero.test.ts`). **A room is kept for the next fight (the user's ask, 2026-10-17):** at the end, Rematch (either player; the first one to tap starts it for both) sets a new `seed` and `from`, the number of the new fight's first move, so moves keep their numbers and the screen replays `moves.slice(from)` (`rematchHeroRoom`; the rules check `from` is exactly where the moves end). A room from before every hero was the same (with `fighters`) can't be joined. **Both phones must run the same `HERO_VERSION`** (a real bug: one phone on the build before the contests played a Stopwatch at once and the fight stalled): a room records the `version` that opened it, a phone on another one can't join and is offered "Reload the latest version" (`versionProblem`), and if `replay` refuses one of the other side's moves mid-fight (`onRefused`), the room says the phones differ and offers the same reload. Nothing about a player is saved: no hero doc, no local hero. The screen shows "Sending your move…" until the server has it (see **Rooms survive a stalled stream**). **Trust trade-off**, as in the party games: the rules can't watch a fight, so a tampered phone could claim a Perfect stop, and a player reading the data could predict the ball and the numbers from the seed (and a tampered phone could claim a full Memory); the app never shows them early.
- **Bluff Table** (`/bluff`, `/bluff/:code`, `src/screens/bluff/`) is the user's ask for a game like Liar's Bar (2026-10-17), **under our own name and words, nothing from the original** (same rule as Ancient Wonders). 2–4 phones, bots welcome (`bot:N` seats played by the host's phone, a beat after each move). A deck of six K, Q, A and two jokers (wild); each round names a table card and deals five to everyone still in; on your turn put 1–3 cards face down claiming they're all the table card, or call the last player a liar: any wrong card and the liar pulls the trigger, all true and the caller does. Each player's revolver has one bullet in six chambers (`bullet`, `pulls`). After a call a new round is dealt, led by whoever pulled (or the next one in); players without cards are skipped, and the last one holding cards must call. Last one standing wins. `src/games/bluff/` is pure TypeScript: `state.ts` (`apply`, `replay`, `mustCall`, `claim`) and `bot.ts`; `tests/unit/bluff.test.ts` checks each rule, hundreds of bot and random games to a winner with their replays, and a golden hash. A call plays out over the table on the phones that see it arrive (`ShowdownView`: the cards turn over, then the revolver). **Data and trust:** `bluffs/{code}` and its `moves/{n}`, exactly like `wonders` (`src/services/bluff.ts`, `tests/rules/bluff.test.ts`), plus Rematch at the end like Hero Gambit's (the user's ask, 2026-10-17: any player starts another game with the same seats; a new `seed` and `from`, and the screen replays `moves.slice(from)`); the deals and bullets come from the seed, so a player reading the data could see every hand. The app only ever shows your own.
- **Sky Ace** (`/sky`, `/sky/play`, `src/screens/sky/`) is a 90s-style vertical shooter for one player (the user's ask, 2026-10-16, after a Raiden screenshot; **our own name and flat vector shapes, nothing from the original**). Drag anywhere and the ship moves with the finger (relative), firing by itself; **lifting the thumb pauses at once**, and any touch on B (bottom left) bombs. **Losing (the user's choice): 3 ships, then Continue from where you are for half the score**, never kicked out. `src/games/sky/sim.ts` is the whole game as pure TypeScript: `step(state, input)` mutates a plain-JSON state one tick (60 a second) for one tick of finger movement, so it runs with hundreds of bullets and the save (`game:sky`, the whole world plus the best score) resumes mid-wave. Waves come from the seed (`wavesFor`), other luck from named hashes, angles from a 64-direction table (trig is banned). Three stages (a city, the sea, a base), each about 2 minutes of waves then a boss whose core is shielded until its guns are down; then the lap starts again, harder. Weapons: Vulcan (red, a widening spread), Laser (blue, straight and strong), homing missiles, bombs; medals from ground targets grow in value until one is missed; a kill right as a plane appears is a Quick shot, double. `render.ts` draws it on a canvas from `--sky-*` tokens; a taller screen shows more ground above and below the 360×640 field. `tests/unit/sky.test.ts` checks each rule, same-inputs and from-a-save replays, a bot pilot clearing all three stages, and a golden hash (bump it with `SKY_VERSION`). **Next (planned): a ranking** whose scores are checked by replaying each run's input log, like the nonogram audit.
- **Rules check shape, not answers:** `firestore.rules` copies `NONOGRAM_VERSION` and `sizeFor()`; `tests/unit/rulesSync.test.ts` fails if they drift.

## Constraints

- **Catching cheats:** the rules can't make a puzzle, so `npm run audit` (`scripts/audit.ts`) remakes each level and day and reports saved grids that don't match the clues. It's read-only; run it by hand against production with `AUDIT_PROJECT_ID=<id>`.
- **Spark plan:** no Cloud Functions, no Cloud Storage. `firestore.rules` is the only server-side validation, so every client write needs a matching rule and a test in `tests/rules/`.
- **Old data stays and is closed.** Neon Flap's data (`users/*`, `leaderboards/*`, `items/*`) and the auto-battler's (`runs/*`, `puzzles/*`, `rankings/*`, `dailyRankings/*`), plus this game's removed daily puzzle (`dailySolves/*`), the removed Rival Wonders' rooms (`duels/*`) and Island Settlers' (`isles/*`) and Hero Gambit's removed Summon, arena and hero docs (`wardrobes/*`, `arena/*`, `heroes/*`), and the removed Stick Brawl's rooms (`brawls/*`, deleted by the user on 2026-10-15; its `game:brawl` save is just no longer read), are left in Firestore, because deleting them would only spend quota. The rules deny all of it except a player reading their own `users/{uid}`, which the app does once to carry their name over. Auto-battler `players` docs keep their extra run fields; renaming still works. `tests/rules/legacy.test.ts`, `tests/rules/solves.test.ts` and `tests/rules/hero.test.ts` cover this.
- **Show only what's needed now** (the user found the screens too complicated). A game screen centres on the decision in front of you, with one line about you. Everything else (other players, full city details, history, options, rules) folds into a one-line `SummaryRow` that opens a `Sheet` (`src/components/`), so it stays one tap away. Party games share `GameHome` and `Lobby` (`src/components/RoomSetup.tsx`), with lobby options under Options. Home shows its Continue button only for a room whose game is still on (`lastRoom()` in `src/lastPage.ts`; each room calls `forgetRoom` when its game ends).
- **Train-friendly is the brief:** keep everything reachable with one thumb (controls at the bottom), make nothing depend on sound, add no timers or fail states, and save every change at once.
- **A plain look for now (the user's choice, 2026-10-11: "remove gacha and all design, use stickman for now").** It replaced a run of styled looks (Plants vs. Zombies–style garden, Cartoon Network–style, Adult Swim–style slime, cartoon stickers, dark-and-gold); all of them, with their creature sprites, attack effects, meme lines, avatars and bundled fonts, are gone (in git history if wanted). A light grey page (`--bg` `#f2f2f4`), white cards, one blue accent, the system font, stick figures, and plain animations for the skills. Colours are still written only in `:root`; `--bg` is repeated in `index.html`'s boot styles and the manifest colours (`vite.config.ts`), so change them together. The app icons (`public/icon.svg` and its PNGs) still show the old sprout. The other hidden games keep their own token colours.
- **Never rename the storage keys `game:nonogram`, `game:library`, `game:lastPage`, `game:hero`, `game:heroLocal`, `game:sky` or `game:wardrobe`** (`game:library` now holds knowledge topics and saved cards, and kept its name from when it also held book highlights; `game:hero` held the removed bot ladder and skill tree, and `game:wardrobe` the removed Summon's look, costumes and gems; neither is read now). A new name would wipe them on every device. Old saves carry fields from removed features (the daily puzzle, highlights); the stores ignore them.
- **Hosting cache headers** in `firebase.json` match the *requested* path, not the file served. The no-cache rules therefore use `/` and `/*` (the app's routes, which all serve `index.html`); `/assets/**` has two segments, so hashed assets keep their immutable caching. Without this, a deploy can be masked for an hour by a cached page.
- After a deploy, the first visit is served from the offline cache and runs the **previous** version, which may not match current rules. `src/main.tsx` swaps in the new build once the player is off the puzzle (`/`) or the app is in the background, and Settings (⋯ → Settings) has "Reload the latest version" (`src/reload.ts`), which clears the service worker and caches.
